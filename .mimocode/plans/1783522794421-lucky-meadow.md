# Unified Window Refactor — Bloom

## Goal
Merge 4 Tauri windows (main, dock, volume-overlay, brightness-overlay) into 1 full-screen transparent window. Keep settings as a separate on-demand window (destroyed on close). This reduces WebView2 processes from ~29 to ~6-8, saving ~600-800 MB.

## Architecture

**Before:** 5 windows, 5 HTML entry points, 5 React roots, 5 separate WebView2 processes
**After:** 1 unified window (main+dock+overlays) + 1 on-demand settings window

```
┌──────────────────────────────────────────────────────┐
│  Unified Window (full-screen, transparent, alwaysOnTop) │
│                                                      │
│  ┌──────────── Notch (top-center) ──────────────┐    │
│  └──────────────────────────────────────────────┘    │
│                                                      │
│  ┌─Vol┐                                ┌─Br┐        │
│  │    │                                │   │        │
│  └────┘                                └───┘        │
│                                                      │
│  ┌─────────────── Dock (bottom) ──────────────────┐  │
│  └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘

┌──────────────────┐
│  Settings Window │  (separate, destroyed on close)
│  (620x480)       │
└──────────────────┘
```

## Step-by-Step Implementation

### Step 1: Merge Vite config to single entry point

**Files:** `vite.config.ts`, `index.html`

- Change `vite.config.ts` rollup input from 5 entries to 1: `main: "index.html"`
- `index.html` stays as-is (already loads `src/main.tsx`)
- Delete `dock.html`, `volume-overlay.html`, `brightness-overlay.html`, `settings.html`
- **Verify:** `bun run build` produces a single `dist/` output

### Step 2: Create unified React root

**Files:** `src/main.tsx`, `src/UnifiedApp.tsx` (new)

- Create `src/UnifiedApp.tsx` that imports and renders all 4 components:
  - `<Notch />` (extracted from App.tsx, the `.bloom` motion.div)
  - `<Dock />` (existing Dock.tsx component)
  - `<VolumeOverlay />` (existing VolumeOverlay inner component, NOT the createRoot wrapper)
  - `<BrightnessOverlay />` (existing BrightnessOverlay inner component, NOT the createRoot wrapper)
- Position each via CSS within a full-screen transparent container:
  - Notch: `position: absolute; top: 0; left: 50%; transform: translateX(-50%)`
  - Dock: `position: absolute; bottom: 0; left: 50%; transform: translateX(-50%)`
  - Volume: `position: absolute; left: 0; top: 50%; transform: translateY(-50%)`
  - Brightness: `position: absolute; right: 0; top: 50%; transform: translateY(-50%)`
- Update `src/main.tsx` to render `<UnifiedApp />` instead of `<App />`
- **Key change:** Each component is now a child of the same React tree. They can share state via React context or props instead of Tauri events for intra-window communication.
- Theme initialization (`initTheme()`) called once at the root level, not per-component.
- Remove the `getCurrentWebviewWindow().label` checks in App.tsx (lines 237-239, 246, 297, 304, 332-337, 377, 415) — everything is now in the "main" window.

### Step 3: Refactor components for unified window

**Files:** `src/App.tsx`, `src/Dock.tsx`, `src/VolumeOverlay.tsx`, `src/BrightnessOverlay.tsx`

**App.tsx (Notch):**
- Remove `getCurrentWebviewWindow().label` checks — always behave as "main" window
- Remove the `window.show()/window.hide()` visibility logic (lines 267-362) — visibility is now CSS-based (`opacity`, `pointerEvents`)
- Keep all Tauri `invoke` calls for backend operations (init_dock, sync_appbar, etc.)
- Keep Tauri event listeners (settings-changed, notch-overlap, etc.)

**Dock.tsx:**
- Remove `getCurrentWebviewWindow().isVisible()` polling (lines 70-101) — dock is always "visible" in the DOM, CSS controls display
- Remove the `window.show()/window.hide()` logic — use CSS visibility
- Keep all Tauri `invoke` calls (get_active_windows, capture_window_thumbnail, etc.)
- Keep Tauri event listeners (dock-overlap, dock-edge-hover, settings-changed, visibility-change)

**VolumeOverlay.tsx:**
- Extract the inner `VolumeNotch` component and `VolumeOverlayApp` logic (minus the `createRoot` wrapper)
- Remove `appWindow.show()/appWindow.hide()` (lines 206-232) — visibility is CSS-based
- Keep Tauri event listeners (volume-change, volume-edge-hover, settings-changed)
- Keep Tauri `invoke` calls (set_volume, load_settings, hide_native_osd)

**BrightnessOverlay.tsx:**
- Same pattern as VolumeOverlay — extract inner component, remove window.show/hide
- Keep Tauri event listeners and invoke calls

### Step 4: Create CSS layout for unified window

**Files:** `src/UnifiedWindow.css` (new)

- Full-screen transparent container: `width: 100vw; height: 100vh; position: fixed; top: 0; left: 0; overflow: hidden`
- Each component positioned absolutely within this container
- Background: `background: transparent` (window is transparent)
- Ensure `pointer-events: none` on the container, `pointer-events: auto` on interactive components
- This lets clicks pass through transparent areas to windows behind

### Step 5: Update Tauri config

**File:** `src-tauri/tauri.conf.json`

- Remove windows: `volume-overlay`, `brightness-overlay`, `dock`
- Keep `main` window but change its properties:
  - Remove fixed `width`/`height`/`x`/`y` — will be sized dynamically by Rust
  - Set `width: 1920, height: 1080` as defaults (will be overridden by Rust on startup)
  - Keep: `transparent: true`, `decorations: false`, `alwaysOnTop: true`, `visibleOnAllWorkspaces: true`, `skipTaskbar: true`, `shadow: false`, `visible: false`, `dragDropEnabled: false`
- Keep `settings` window as-is but add `"visible": false`
- **Verify:** App starts with 2 windows (main hidden, settings hidden)

### Step 6: Update Rust backend — window management

**Files:** `src-tauri/src/main.rs`, `src-tauri/src/commands.rs`, `src-tauri/src/services.rs`, `src-tauri/src/state.rs`

**main.rs setup:**
- Remove `dock_win` references (no separate dock window)
- Remove `volume-overlay` and `brightness-overlay` window event handlers
- Keep `main` window event handler (Moved/Resized → sync position, ScaleFactorChanged → register_appbar)
- Remove settings window mica effect (will be re-added when settings window is created on-demand)
- Settings on-demand creation: modify `open_settings_window` to create the window if it doesn't exist, or show it if it does. Add a `CloseRequested` handler that destroys the window (instead of hiding it).
- Tray menu: keep "Open Settings", "Restart", "Quit"

**commands.rs changes:**
- `init_dock` → Remove window references. The dock is now rendered in the main window. Keep the AppBar registration and taskbar hiding logic, but apply them to the main window.
- `toggle_dock` → Simplified: show/hide dock is now CSS-based (emit event to frontend)
- `change_dock_mode` → Simplified: emit event to frontend, keep AppBar logic
- `change_notch_mode` → Keep as-is but reference "main" window only
- `sync_appbar` → Keep for main window, remove dock window references
- `hide_volume_overlay` → Remove (no separate window to hide)
- `hide_brightness_overlay` → Remove (no separate window to hide)
- `open_settings_window` → Create settings window on-demand if not exists, show + focus. Add destroy-on-close behavior.
- `set_window_height` → Keep (used by main window)
- `resize_settings_window` → Keep (used by settings window)
- Remove `set_dock_hovered`, `set_notch_hovered` → These can become local frontend state since everything is in one window
- Remove `update_dock_rect`, `update_notch_rect` → Replace with a single `update_component_rect` that tracks all component bounds for cursor hit-testing
- `set_menu_open` → Keep (used by cursor monitor for dock menu hit-testing)
- Remove `hide_volume_overlay`, `hide_brightness_overlay` commands

**services.rs changes:**
- `sync_overlays` → Remove (no separate overlay windows to position)
- `setup_cursor_monitor` → Major refactor:
  - Instead of managing 5 separate windows, manage 1 unified window
  - Track component rects (notch, dock, volume, brightness) from frontend
  - Cursor hit-testing against component rects to determine `ignore_cursor_events`
  - Emit `component-hover` events to frontend for hover state
  - Keep edge-hover detection for volume/brightness overlays
  - Keep dock bottom-edge detection
  - Keep notch top-edge detection
- `setup_system_worker` → Remove `get_webview_window("bottom-corners")` reference (line 568)
- `register_appbar` → Keep for main window
- `register_dock_appbar` → Keep but apply to main window (dock is part of main window's AppBar reservation)
- `reposition_all_windows` → Simplified to reposition main window only

**state.rs changes:**
- Remove `DOCK_WINDOW_RECT` (replaced by component rect tracking)
- Keep `MAIN_WINDOW_RECT` (renamed to `UNIFIED_WINDOW_RECT`)
- Add `NOTCH_COMPONENT_RECT`, `DOCK_COMPONENT_RECT`, `VOL_COMPONENT_RECT`, `BR_COMPONENT_RECT` for frontend-reported component bounds
- Remove `DOCK_IS_HOVERED`, `NOTCH_IS_HOVERED` (frontend handles hover state directly)

### Step 7: Frontend ↔ Rust component rect tracking

**New Tauri command:** `update_component_rects` — frontend reports all component bounding boxes to Rust on mount and on resize. Rust uses these for cursor hit-testing.

**Flow:**
1. Frontend mounts → calculates each component's `getBoundingClientRect()` → calls `update_component_rects`
2. Frontend resizes (zoom, mode change) → recalculates → calls `update_component_rects`
3. Rust cursor monitor reads these rects for hit-testing
4. Rust emits `component-hover-state` event → frontend knows which component is hovered

### Step 8: Remove dead code

- Delete `dock-main.tsx` (no longer needed)
- Delete `VolumeOverlay.tsx` and `BrightnessOverlay.tsx` standalone entry wrappers (the inner components are extracted into UnifiedApp)
- Remove the 4 unused HTML files (done in Step 1)
- Clean up any window-label-based conditionals throughout the codebase

### Step 9: Settings window on-demand lifecycle

**Behavior:**
- Settings window does NOT exist at startup
- When user clicks "Open Settings" (tray, notch, or dock menu):
  1. Rust checks if settings window exists → if not, creates it via Tauri's `WebviewWindowBuilder`
  2. Shows and focuses the window
- When user closes settings window:
  1. `CloseRequested` event fires → Rust calls `window.destroy()` (not `hide()`)
  2. Window is fully destroyed, WebView2 process is freed
- Mica effect applied on creation

### Step 10: Test and verify

- Run `bun run dev` → verify all 4 components render correctly in unified window
- Test notch: hover expand, mode switching (scroll wheel), music mode, calendar mode
- Test dock: app icons, pin/unpin, drag reorder, context menus, app previews
- Test volume overlay: hardware volume keys, edge hover, slider interaction
- Test brightness overlay: hardware brightness keys, edge hover, slider interaction
- Test settings: open/close, all toggles work, window is destroyed on close
- Test fullscreen detection: notch/dock hide when app is fullscreen
- Test AppBar: fixed mode reserves screen space correctly
- Test monitor changes: display connect/disconnect, resolution change
- Test autostart: Bloom starts correctly on login
- **Memory check:** Compare WebView2 process count before/after
